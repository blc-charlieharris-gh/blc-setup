The recurring "Creatives Matcher thumbnails missing" (fixed by a re-sync, comes back weeks later) is NOT a fbcdn hotlink/referrer/CSP problem. The stored URLs load fine via curl AND with full browser headers (200). Two real causes:

1. **Untracked-campaign frozen rows (the mass cause).** meta-sync skips syncing child ads of campaigns with `ads_campaigns.is_tracked=false` (Slice B). Those `ads_ads` rows freeze: `status` stays stuck at ACTIVE (they usually ended on Meta) and their signed Meta CDN `thumbnail_url` (has a ~2-4wk `oe=` expiry token) expires and never refreshes. `useMatcherCreatives` used to show ads from untracked campaigns too → blank cards. Fixed 2026-07-30: matcher now filters `campTracked` (is_tracked !== false). Diagnose by decoding `oe=` hex as a unix ts vs now(); expired count ≈ untracked-campaign count (Greentide 78≈77, National Eco 123=123).

2. **Specific video creatives Meta won't give a thumbnail for (PERSISTENT — needs meta-sync fix).** Meta serves `creative.thumbnail_url = ''` (empty string, not null) AND omits image_url for certain video creatives, even hours/days after the ad went live. VERIFIED 2026-07-30: forced a fresh single-client meta-sync for Greentide + Arktek at 11:44; the 6 GT + 3 Arktek empties stayed empty, raw creative came back as just `{id, thumbnail_url:""}`. So it is NOT transient / self-healing (I wrongly claimed that first — the created_at was just the sync-insert time, and a re-sync disproved it). It is creative-specific: other video ads in the same account return thumbnails fine. ROOT CAUSE (proven 2026-07-30 with the real Meta token in `meta-access/.env`; load_dotenv the ABSOLUTE path, it never loads from another cwd): FRESH Instagram-sourced test creatives. Meta only populates `adcreative.thumbnail_url` for these a day-plus AFTER creation. Evidence: broken creative name dated 2026-07-29 → thumbnail_url=''; working one dated 2026-07-16 → populated. Same `object_type: SHARE`, both carry `effective_instagram_media_id`. Charlie's workflow (duplicate ad → remove creative → re-add from gallery) is fine; the creatives are just new. NOT a dead end, NOT "existing post with no asset" (earlier wrong call). **FIXED 2026-07-30 (meta-sync v42, deployed via dashboard, live-verified: Greentide full sync 1982 records clean, 0 empties; Arktek 0 empties):** when `creative.thumbnail_url` is empty, run a bounded per-creative fallback in the ads section — `GET /{creative_id}?fields=effective_instagram_media_id`, then `GET /{ig_media_id}?fields=media_type,media_url,thumbnail_url`, set `thumbnail_url = thumbnail_url ?? media_url`. Only fires for the handful of blank ads; try/catch so an IG failure never aborts the sync. Can't write ads_ads directly (MCP read-only) and IG URLs expire, so it must live in meta-sync (runs every full sync).

**HARD LESSON (v41 regression, do NOT repeat):** the first attempt added `effective_instagram_media_id` to the BULK `/ads` creative expansion (`creative{id,thumbnail_url,image_url,body,effective_instagram_media_id}`). That extra field on the 100-per-page pull made Meta reject Greentide (~500 ads) with HTTP 500 "Please reduce the amount of data you're asking for" on page 1, breaking the ENTIRE Greentide full sync (its critical data pipeline). Arktek (13 ads) passed so it slipped through review. RULE: any change to a bulk field-expansion in meta-sync MUST be tested at limit=100 against the LARGEST account (Greentide act_419073311249744) before deploy — do NOT validate only on a small account. Keep per-empty-ad enrichment OUT of the bulk pull; do it as bounded per-creative follow-up calls. Also: the earlier size-hint / video_id / "SHARE post has no asset" theories were all wrong dead-ends.

**Why:** wasted a cycle earlier suspecting CDN/referrer. Check the DB first: is_tracked chain + `oe=` expiry + empty-string vs null. **How to apply:** for any "matcher/perf image missing", run the tracked-chain + oe-expiry + empty-string breakdown before touching img tags or CSP.
