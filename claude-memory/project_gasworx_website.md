**Blog:** the AI-blog tool is Soro (trysoro.com), was posting to his Wix blog, now switched over to post
to the new site instead (Wix connection disconnected 2026-08-18). `_client/import-soro.mjs` (new

script) into the same `blog-import/` format the old `import-blog.mjs` produced, so `build-pages.mjs`
needed zero changes. Idempotent: matches already-imported posts by Soro's `guid`, falls back to
normalised title for the original 20 (imported before this script existed, no `guid` on those). Ran
2026-08-18: pulled 60 new posts, 80 total now, sitemap → 92 urls.

**Real bug fixed before landing:** the block-extraction regex first ran against the raw RSS `<item>`
block instead of the isolated `content:encoded` body — `<pubDate>` got misread as a fake `<p ...>` tag
("p" + "ubDate" satisfies a `(h[2-4]|p|li)` tag-name group), corrupting every imported post's first
paragraph with the pubDate + description text glued on front. Caught in a spot-check, not automated —
always eyeball at least one freshly-imported post's rendered body text after running this script.

**Old `_client/import-blog.mjs` (Wix RSS) is now dead**, kept for history only, do not run it again,
`import-soro.mjs` is the live pipeline. RSS was chosen over Soro's two other integration options
(a client-side JS widget: no static page = no SEO, defeats the point; a custom webhook: Soro builds
those case-by-case per client, not self-serve, needs a public receiver endpoint on our side too).
